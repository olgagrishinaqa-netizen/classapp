# 2. База данных (миграции) и автотесты

## Миграции: `alembic.ini` и папка `alembic/`

**Зачем.** Схема таблиц в PostgreSQL меняется со временем. Миграция — это скрипт «из версии A в версию B».
Alembic хранит в БД таблицу `alembic_version` с номером текущей версии и применяет только недостающие
миграции. В проде схему меняет **только** Alembic (Job `classapp-migrate` в Kubernetes), а не приложение.

### `alembic.ini`
Конфигурация самого Alembic. Важное: `script_location = %(here)s/alembic` — где лежат скрипты (`%(here)s` — папка файла);
`sqlalchemy.url = postgresql+psycopg2://postgres:postgres@localhost:5432/classapp` — адрес по умолчанию для локальной работы.
В реальных окружениях он **переопределяется** переменной `DATABASE_URL` (см. `env.py`). Остальное — настройки логирования.

### `alembic/env.py` — построчно
| Строки | Что делает |
|---|---|
| 1–6 | импорты: `os` для переменных окружения, `fileConfig` для логов, `engine_from_config` и `pool` для подключения, `context` — API Alembic |
| 8–10 | импорт `db` и `app.models`: модели регистрируются в `db.metadata`, иначе Alembic «не знает» таблиц |
| 12 | `config` — объект настроек из `alembic.ini` |
| 14–19 | если задана `DATABASE_URL`, она подставляется вместо URL из ini. `%` удваивается (`%%`), потому что ConfigParser воспринимает `%` как спецсимвол, а пароль в URL может содержать `%21` |
| 21–22 | включает логирование по настройкам ini |
| 24 | `target_metadata` — «эталонная» схема из моделей |
| 27–35 `run_migrations_offline` | режим «только сгенерировать SQL» без подключения (`literal_binds`) |
| 38–47 `run_migrations_online` | основной режим: подключается к БД (`NullPool` — без пула, соединение закрывается сразу), открывает транзакцию, применяет миграции |
| 50–53 | выбирает режим по флагу запуска |

### `alembic/script.py.mako`, `alembic/README`
Шаблон, по которому `alembic revision` создаёт новые файлы миграций, и стандартный README Alembic.

### `alembic/versions/` — цепочка миграций (порядок важен)
Каждая миграция имеет `revision` (свой номер) и `down_revision` (номер предыдущей). Функция `upgrade()`
применяет изменение, `downgrade()` откатывает.

| № | Файл | Что делает |
|---|---|---|
| 1 | `20260915_01_baseline_schema_and_last_login` | создаёт все таблицы по текущим моделям (`db.metadata.create_all`) и добавляет `user.last_login`, если его нет. Подходит и для новой БД, и для БД, созданной до Alembic |
| 2 | `20260918_01_add_students_table` | таблица `students` с уникальностью «фамилия+имя» и индексами. Если таблица уже есть (создана миграцией 1) — только добавляет ограничение. Это защита идемпотентности |
| 3 | `20260928_01_payment_student_id` | взносы привязываются к ученику (`payment.student_id`) вместо учётной записи родителя |
| 4 | `20260928_02_add_task_deadline` | необязательный дедлайн у задачи |
| 5 | `20260930_01_add_schedule_bell_schedule_general_info` | таблицы расписания уроков, расписания звонков и общей информации |
| 6 | `20260930_02_add_task_priority` | приоритет задачи |
| 7 | `20260930_03_add_news_images` | таблица `news_image`; старые одиночные картинки копируются в неё |
| 8 | `20261001_01_add_login_event` | таблица журнала входов `login_event` с индексами. Текущая версия БД на ВМ |

Паттерн «сначала проверить, потом создать» (`if ... not in inspector.get_table_names()`) делает миграции
**идемпотентными**: повторный запуск ничего не ломает. Это важно, потому что Job миграций может повторяться (`backoffLimit: 4`).

Команды: `alembic upgrade head` (применить всё), `alembic current` (текущая версия), `alembic downgrade -1` (откат на шаг).

## Автотесты (`tests/`, `pytest.ini`)

**Зачем.** Проверять, что приложение работает, прежде чем образ попадёт в прод. Запускаются в CI на каждый коммит.

### `pytest.ini`
`pythonpath = app` и `testpaths = tests`: где искать код и тесты.

### `tests/conftest.py` — общие заготовки (fixtures)
| Элемент | Что делает |
|---|---|
| `TestConfig` | конфиг только для тестов: `TESTING=True`, отключена CSRF-защита форм (`WTF_CSRF_ENABLED=False`), БД — SQLite-файл или `TEST_DATABASE_URL`, лог в `/tmp` |
| fixture `app` (на всю сессию) | создаёт приложение, `create_all()` создаёт таблицы, после тестов `drop_all()` удаляет |
| fixture `client` | тестовый HTTP-клиент Flask |
| fixture `db` | доступ к объекту БД для подготовки данных |

Админ для тестов создаётся самим приложением при старте: телефон `375290000000`, пароль `admin123` (значения по умолчанию из `config.py`).

### Что проверяет каждый файл

| Файл | Проверяет |
|---|---|
| `test_health.py` | приложение создаётся; `/healthz` отвечает ok и сообщает о статусе БД |
| `test_auth.py` | вход (форматы телефона, неверный пароль, «битый» хэш), создание и изменение пользователей, права, финансы (взносы/расходы), смена роли, bootstrap и сброс пароля админа |
| `test_routes_hardening.py` | защита: `/uploads` требует входа, нельзя разжаловать последнего админа, недопустимые расширения файлов отклоняются, чеки хранятся в `UPLOAD_FOLDER` и недоступны без входа |
| `test_tasks.py` | создание задач с полями, обязательность названия, права, приоритеты, сортировка активных задач |
| `test_news_images.py` | новости с картинками: создание, добавление/удаление при редактировании, лимит 10, удаление файлов вместе с новостью |
| `test_schedule.py` | расписание уроков и звонков, общая информация: создание, дубли, правка, права родителя |
| `test_students.py` | состав класса: правка, дубль имени, удаление, права |
| `test_login_log.py` | журнал входов: запись в БД, страница админа, фильтр, права, описание устройства |
| `test_audit.py` | аудит: успешный и неудачный вход, маскировка телефона, действия, выход, метрики Prometheus |
| `test_dashboard.py` | дашборд: последняя новость, блок картинки, расходы за месяц |
| `test_logging.py` | приложение пишет JSON-лог в файл |
| `test_api_regression.py` | защищённые API-коллекции требуют авторизации |

Итого 78 тестов. Запуск: `pytest -q`. С отчётами: `pytest --junitxml=reports/junit.xml --cov=app`.

### `tests/load/locustfile.py` — нагрузочный тест
Класс `ClassappUser` имитирует администратора: `on_start` входит через `/api/login`, затем задачи `@task(вес)`
случайно открывают дашборд, задачи, новости, расходы (вес = как часто). Между действиями пауза 1–3 с.
Запуск: `locust -f tests/load/locustfile.py --host=http://localhost:8000`.
